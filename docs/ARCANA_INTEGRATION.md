# 아르카나 : ARCANA — 시작 맵 통합

## 기준과 실행

사용자 요청에 따라 `docs/ARCANA_module`을 새 스토리·데이터 구조의 기준으로 삼는다.
원본 DB의 내부 제목 `혈통의 법칙 : BLOOD & PRINCIPLE`은 원본 보존을 위해 그대로 두고,
게임 창과 새 기본 모드 HUD는 **아르카나 : ARCANA**로 표시한다.
기존 실행 파일명과 Visual Studio 솔루션명은 호환성을 위해 `SimpleGame`을 유지한다.

- 기본 실행 또는 `--arcana`: 북부 숲의 불탄 집에서 시작.
- `--lena`: 기존 수로/레나. `--tutorial`/`--village`: 장례 마을. `--level-one`: 사냥터.
- H 시작/일시정지, WASD 이동, E 조사·대화·유품·흡수, SPACE/왼쪽 클릭 파란 구체 발사.
- 구체는 8 월드 단위 안의 가장 가까운 가시 적(마수·산적·플레이어를 공격 중인 대상)을
  조준한다. 적이 없으면 마지막 실제 이동 방향으로 발사한다. 첫 이동 전 기본 방향은 화면 아래다.
  기본 공격은 마력 소모 없이 기존 24 피해/0.55초 간격을 유지하며, 발사 즉시가 아니라 접촉 시 피해를 준다.
  지형에 막히거나 1.2초가 지나면 소멸한다. 비적대 주민·일반 동물·항복한 대상은 맞지 않는다.
  구체와 시전 동작은 일시 효과로 저장하지 않으며 불러오기 시 제거한다. F 화염은 별도 유지한다.
- F 화염: 가장 가까운 가시 대상에게 사용하므로 주민도 피격 가능.
- 대장간에서 이동하지 않고 Q 유지: 안전할 때 현재 마력 회복. 최대 마력은 불변.
- V 보유 식량 섭취, 호숫가 음수 지점에서 E로 갈증 해소.
- K 저장, L 불러오기, R 새 게임, ESC 종료.
- ARCANA 시간은 실제 시뮬레이션 1초 = 세계 시간 1초. 일시정지 중 진행하지 않는다.
  레나의 기존 시간 배율은 유지한다.

미니맵은 오른쪽 상단에 제목 패널과 나란히 배치한다. 실제 지형 패치와 호수 경계를
재사용해 땅·길·호수·숲·건물을 그리고, 표식까지 실제 화면과 같은 쿼터뷰 방향으로 투영한다.
일반 사슴·늑대 등 야생동물 표식은 숨기고 주민·플레이어·마수 표식은 유지한다.
WASD는 화면 기준 상하좌우이며 대각선 입력도 정규화한다. 플레이어의 작은 프레임별
이동을 NPC 도착 허용 오차로 무시하지 않는다. 장애물 앞에서는 충돌/미끄러짐을 유지한다.

## 첫 플레이 흐름

| 단계 | DB ID | 실행 |
|---|---|---|
| 부모의 집 조사 | prologue / p1 | 시작 지점의 재가 된 집에서 E |
| 수첩·은빛 문장 | prologue / p2 | 집에서 다시 E, 일회성 소유 상태 기록 |
| 세르딘 조우 | meet_serdin / s1 | 북동쪽 숲길의 세르딘 가까이에서 E |
| 풀무 관찰 | forge / f1 | 미니맵 금색 대장간에서 E |
| 도식 확인 | forge / f2 | 대장간에서 다시 E |
| 연소 실험 | forge / f3 | 대장간에서 F, 연소 지식 획득 |
| 기사단 문장 | knights / k1 | 초소에서 E, 첫 장 연결 완료 |

목적 문구는 DB에서 읽는다. 명시된 단계의 실행 처리는 C++ 어댑터로 연결한다.
JSON에 적힌 임의 명령을 실행하는 범용 스크립트 엔진은 아니다.
유품 소유와 지식은 진행 상태에 묶여 저장되며, 아직 범용 인벤토리 화면은 없다.
세르딘/브란 사망 시 유품의 편지/남겨진 풀무 장치로 이어지는 경로는 이번 맵의 보완 설계다.
세르딘을 만나기 전 후반 비밀·신의 검열 정답을 공개하지 않는다.

## 맵과 인구

좌표가 비어 있는 원본 데이터를 쿼터뷰 한 청크로 배치했다. 북서쪽 불탄 집/북부 숲,
중앙 벨하임, 대장간과 기사 초소, 동남쪽 마수 영역, 동쪽 호수로 구성한다.
원본의 region ID는 유지하지만 여러 대륙 전체를 한 지도에 옮긴 것은 아니다.
아르센의 이셀은 DB에서 읽더라도 시작 맵에 임의 배치하지 않는다.

- 벨하임 120명: 브란·레온·토마스·엘라 + 일반 주민 116명.
- 별도 플레이어·세르딘, 테스트 충돌을 위한 외부 약탈자 3명.
- 사슴 28, 일반 늑대 9, 흑아 멧돼지 마수 3. 시작 Actor 개체 합계 165.
- `populations`는 이미 명시된 같은 지역·종의 개체를 **포함하는 총수**로 해석한다.
  따라서 wolf_01/beast_01을 다시 더하지 않는다. 원본에 집계 포함 여부 명세가 없어
  이 정책을 어댑터의 명시적 가정으로 둔다. 생성 ID는 `arcana:*`로 구분한다.
- 일반 주민의 역할 배분·생활 좌표·약탈자·엘라의 약품 8개는 맵 제작용 보완 데이터다.
  원본 DB에 존재하는 인벤토리라고 주장하지 않는다.
- 초기 창고 식량·재정·치안은 DB 값을 사용한다. 재생성으로 죽음을 취소하지 않는다.
- 시작 구호 정책으로 기존 재정에서 플레이어에게 최대 2은화, 일부 노동자에게 2은화를
  이전하고 기존 창고에서 상인에게 최대 2배급씩 배분한다. 합계 자원은 증가하지 않는다.

## 구조

`ArcanaWorld.cpp`는 원본 `bp::native::load`와 `Scheduler`를 사용한다.
`ArcanaNative.cpp`가 원본 소스를 연결하며 옛 `content.cpp/simulation.cpp`는 링크하지 않는다.
DB TEXT ID ↔ Actor ID 대응을 유지하고 SceneGraph가 살아 있는 객체와 사체를 소유한다.
기존 RenderQueue, 스프라이트/모델 캐시, 물·불 셰이더와 후처리를 재사용한다.

WBG는 39개 원본 노드와 종별 enabled/base_weight를 읽는다. 실제 후보는 대기·배회·이동,
수면·섭식·음수·노동·휴식·대화·거래·치료·동행·위협·절도·항복·공격·도주·사냥·애도·신고다.
감지/기억은 공통 지각 서비스가 담당한다. 나머지 미구현 노드를 빈 실행기로 등록하지 않는다.
후보 점수는 엔진 측 초기 정책이며 욕구·위협·역할을 정규화해 제공한다.
DB 최소 유지 시간과 히스테리시스, 비상 중단 규칙을 적용한다.

NPC–NPC 약탈·치료·거래·살해, 포식자–먹이 사냥, 마수–주민 교전과 경비 개입은
실제 이동/시야/접촉/자원 검사를 거친다. 일반 초식동물은 비활성 Attack/Kill을 실행하지 않는다.
마수는 기본적으로 영역 주변에 머물고 hunger > 75 또는 disturbance > 80일 때 마을로 이동한다.
현재는 플레이어의 마수 공격이 교란을 올린다. 유인/번식/영역 상실 사건은 아직 연결하지 않았다.
신고 3건 이상·치안 40 미만·생존 레온 조건에서 현장 조사 출동을 한 번 생성한다.
신고만으로 범인을 순간이동시키거나 자동 처형하지 않는다.

## 마법과 죽음

- 화염 기본 소모와 연소 효율 배수는 DB에서 읽는다. 풀무 실험은 연료·산소 조건을
  대장간 지점으로 모델링한다. 지식을 배워도 조건 밖에서 할인하지 않는다.
- 지식은 최대 마력을 늘리지 않는다. Q 휴식도 현재 마력만 회복한다.
- 흑아 멧돼지 사망 후 E: 주인공의 명시된 혈통, 직접 피해 기여, 근접/시야,
  세계 시간 60초 제한을 검사한다. 인접한 구경꾼에게 자동 지급하지 않는다.
- `bp::native::manaGain`의 상대 전력·종류별 반복 감소 공식을 사용한다.
  현재 첫 맵에는 마수 종류가 흑아 멧돼지 하나이므로 해당 종류의 사냥 횟수를 보관한다.
  다른 마수 종류를 추가할 때 반드시 종별 기록으로 확장해야 한다.
- 사망·흡수 완료·기여 여부·현재/최대 마력·반복 횟수는 하나의 월드 저장에 함께 기록된다.

## 저장과 의존성

`%LOCALAPPDATA%/SimpleGame/arcana-save-v1.txt`에 전체 스냅샷을 저장한다.
원본 DB와 빌드 옆 배포 DB는 읽기 전용 콘텐츠다. 이 통합은 모듈의 별도 `RuntimeStore`를
병행 호출하지 않는다. 두 저장소 간 마력/사망 불일치를 피하도록 게임 저장 계층이 단일 소유한다.
WBG 행동 시간, 퀘스트, 지식, 사망, 재고, 사실·목격 기억, 마력, 파견 상태를 함께 저장한다.
레나 저장과 헤더/슬롯이 다르며 교차 불러오기를 거부한다. 임시 파일 성공 후에만 교체한다.
원본 시드 인원/ID/레이아웃 계약을 바꾸면 세이브 버전과 마이그레이션도 함께 변경해야 한다.

Visual Studio 프로젝트는 C++17, `/utf-8`(새 소스), Windows SDK winsqlite3로 연결했다.
별도 SQLite 설치/다운로드는 하지 않았다. Windows의 SQLite에 JSON 함수가 필요하다.
사용자 빌드 시 `assets/arcana/blood_principle_game.db`를 실행 파일 옆으로 복사한다.
현재 작업 디렉터리가 아니라 실행 파일 위치를 기준으로 찾는다. 누락/규격 오류가 나면
메시지와 콘솔 오류를 내고 중단하며, 예전 레나 맵으로 조용히 되돌아가지 않는다.

## 모니터링과 계측

기존 로컬 수신기/HTML을 그대로 사용한다. 월드 ID는 `WORLD_ARCANA_BELHEIM`, 마을 ID는
`belheim`이다. 실제 배치 개체만 전송하고 원격 도시 인구를 가짜 Actor로 보고하지 않는다.
NPC 마력, 최대 체력, 마수 여부, 흡수 여부와 quest_step/교란/파견 상태를 추가했다.
추가 CPU/counter/gauge 키와 해석은 `PERFORMANCE_PROFILING.txt`를 따른다.

## 구현하지 않은 범위

DB의 모든 내용이 실행 가능한 완성 게임이 된 것은 아니다. 2장 이후 퀘스트와 원격 지역,
전역 LOD/지역 이동, 결혼·출생·상속·계약, 전체 범죄 수사/예산·기사단 편성,
일반화된 주문 환경/혈통·다중 기여 원장, 39개 행동 전부의 실행기는 남아 있다.
원본 DB의 SQL 저장 스키마로 전체 진행 상태를 다시 쓰는 기능도 아직 없다.
토마스의 동적 도적화는 구현하지 않았고 별도의 약탈자들로 현재 교전 경로를 구성했다.

## 사용자 확인

빌드·게임 실행·자체 테스트는 이번 작업에서 수행하지 않았다.
사용자 빌드 후 기본 모드가 불탄 집인지, 창 이름/한글 표시, 퀘스트 순서, 주민과 마수 교전,
대장간 안/밖 마법 소모, 흡수 제한, 사망/저장 복원, 모니터 상태를 확인한다.
`SimpleGame.exe --arcana-self-test`는 창 없이 기본 개체 수·연결 배치·퀘스트·효율과 최대 마력
분리·흡수 중복 방지·저장/불러오기를 검사하는 선택적 사용자 실행 경로다.
검사 파일은 고유 임시 파일이며 실제 게임 저장 슬롯을 사용하지 않는다.
8방향 이동 검사는 60/120Hz 입력 변위를 화면으로 재투영하여 방향과 속도를 비교한다.
추가 수동 확인: A/D 단독 이동, W/S 및 대각선 이동, 호수/집 충돌, 미니맵 지형·표식 방향,
창 크기 변경 시 제목과 미니맵의 분리 상태를 확인한다.
