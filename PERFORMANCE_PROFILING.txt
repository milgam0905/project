렌더 최적화 / AI 분석용 프로파일링
================================

1. 적용된 구조

- 미니맵 바탕: 40 x 36셀의 개별 그리기 대신 캐시 RGBA 텍스처 한 장.
  PrepareHuntingMap은 최초 생성 및 N 맵 재생성 때 호출한다.
  플레이어/적 등 동적 표식만 매 프레임 갱신한다.
- RenderQueue: Begin/Vertex/TexCoord/Color/End로 배치 데이터를 등록한다.
  Quad/Fan/Strip은 삼각형 인덱스로, LineLoop/LineStrip은 선분으로 변환한다.
  동일 토폴로지·텍스처 상태의 연속 명령을 하나의 glDrawElements로 제출한다.
  GPU VBO/인덱스 버퍼를 사용하며 정점 색상·UV·투명도는 배치를 나누지 않는다.
- 그림자/도형/HUD: 위 큐를 사용한다. 그림자 패스는 여러 타원을 함께 제출한다.
- 수면: 맵별 삼각형 메시를 GL_STATIC_DRAW로 캐싱하고 셰이더 시간만 갱신한다.
  첫 레벨 수면은 한 메시, 튜토리얼 호수는 경계가 바뀔 때만 재생성한다.
- 스프라이트: 기존 모델/캐릭터 아틀라스를 사용하고 동일 상태의 연속 스프라이트를 합친다.
  다른 텍스처·체력바·셰이더가 사이에 끼면 순서 보존을 위해 배치를 분리한다.
- 텍스트: 문자열별 텍스처 대신 32 x 32셀 글리프 아틀라스를 사용한다.
  최대 2048 x 2048 RGBA(16 MiB, 4096글자). GPU 제한에 따라 더 작아질 수 있다.
  숫자 변경은 기존 글리프를 재사용한다. 가득 차면 가장 오래 쓰지 않은 슬롯만 교체한다.
  슬롯 교체 전에는 큐를 제출하므로 대기 중인 글자가 바뀌지 않는다.
  기존 UI의 BMP 한글/라틴 문자용이며 복잡한 문자 조형/커닝/이모지 엔진은 아니다.
  UTF-16 보조 평면 문자는 대체 문자로 표시한다.
- 현재 OpenGL 2.1 compatibility 경로를 유지한다.
  후처리의 fullscreen 3패스만 명시적으로 flush한 즉시 모드 그리기를 유지한다.

2. 배칭에서 반드시 지켜야 하는 규칙

SceneGraph가 먼저 깊이를 정렬한다. RenderQueue는 순서를 절대 바꾸지 않는다.
따라서 반투명 오브젝트의 가림 결과를 보존한다.
Actor별 논리/위치/소유권과 GPU draw call은 별개다.

RenderQueue::Texture/EnableTexture/Color/TexCoord는 제출할 정점/명령의 상태를 기록한다.
이 API는 즉시 GL 상태를 바꾸는 함수가 아니다.
다음 변경 전에는 Flush가 필요하다:
  셰이더 및 uniform 의미 변경, 블렌딩, 행렬, FBO, viewport, scissor,
  대기 중인 명령이 사용하는 텍스처/버퍼의 덮어쓰기 또는 삭제.
제공한 Program/Blend/PushMatrix/PopMatrix/Translate는 이 경계를 처리한다.
각 렌더 패스 종료, 후처리 시작, swap 전에도 큐를 비운다.
빈 Flush는 실제 draw call을 만들지 않는다.

현재 상태 키는 texture + texture enable + triangles/lines이다.
셰이더/블렌딩/행렬/FBO는 flush 경계로 구분된다.
멀티텍스처나 새 uniform 조합을 도입할 때 이 제약을 함께 확장해야 한다.

3. 로그 사용 방법

기본 실행: 콘솔 + JSONL 파일에 프로파일링을 출력한다.
--tutorial: 튜토리얼에 동일한 프로파일링을 적용한다.
--no-profile: 타이머/통계 로그/GPU query를 끈다. 최적화 자체는 유지된다.
자동 빌드나 실행은 하지 않는다.

파일:
  %LOCALAPPDATA%\SimpleGame\Profiles\profile-<PID>-current.jsonl
  %LOCALAPPDATA%\SimpleGame\Profiles\profile-<PID>-previous.jsonl

current가 약 8 MiB를 넘으면 previous로 회전한다.
동일 PID의 이전 previous는 교체된다. 프로세스별 최근 약 16 MiB를 유지한다.
서로 다른 PID의 이전 실행 로그는 자동 삭제하지 않는다. 필요할 때 사용자가 정리한다.
파일 생성/회전/쓰기 실패 시 콘솔 출력은 유지되고 logging.file_available이 0이 된다.
콘솔에는 기존 캐시/셰이더 메시지도 섞일 수 있으므로 자동 분석은 JSONL 파일을 사용한다.
profiling 파일에는 성능 수치와 GPU 식별 정보만 넣고 게임 대사나 사용자 입력은 넣지 않는다.

schema: simplegame.profile.v1
event:
  session_start          모드, PID, debug/release, GL 버전/GPU 및 GPU 계측 지원 여부
  profile_window         약 1초 집계(게임이 프레임을 제출하지 않으면 보고도 지연됨)
  frame_interval_spike   프레임 시작 간격 >33.333ms. 최대 1초에 한 번 알림
  session_end            정상 종료
profile_window.phase:
  startup / runtime / shutdown

로그는 JSON 한 줄당 하나의 레코드다.
키 이름은 안정적인 ASCII 영문, 숫자는 로케일에 무관하게 소수점 '.'을 사용한다.

4. 핵심 필드와 해석

fps:
  집계 구간에 완료한 렌더 프레임 수 / 실제 경과 초.
  16ms GLUT 타이머와 swap/VSync 대기 영향을 포함한다.
  약 60 FPS가 유지된다는 이유만으로 최적화 효과가 없다고 판단하면 안 된다.

frame_interval_ms / frame_interval_p95_ms:
  렌더 프레임 시작 간 실제 간격. 업데이트, 타이머, OS 지연, 로깅 영향을 포함한다.
  p95는 구간 내 최대 4096개 간격 샘플에서 계산한다.

render_and_swap_cpu_ms:
  BeginFrame부터 swap 완료까지 CPU에서 관찰한 벽시계 시간.
  별도 GLUT Update 콜백 실행 시간은 이 값에 포함되지 않는다.
  GPU query poll/간격 spike 로그 비용은 들어갈 수 있다.

draw_calls_per_frame:
  GPU 제출 단위의 실제 API 호출 수(glDrawElements + fullscreen glBegin).
  이전 버전처럼 도형 하나당 1회를 세는 값이 아니다.
  드라이버 내부 명령 병합/하드웨어 dispatch 수를 의미하지 않는다.

source_primitives_per_frame:
  배칭 전 등록한 도형/스프라이트/글리프/정적 메시 명령 수.
  triangle 수가 아니며 예전 문자열별 카운터와 일대일 비교할 수 없다.

각 Metric 객체:
  samples, sum, avg, min, max
  cpu/gpu/frame 시간의 단위는 ms, draw/source 객체는 호출 수.
  CPU avg는 호출 1회 평균이다. 프레임당 비용은 runtime.sum / frames로 분석한다.
  여러 번 호출되는 AI/길찾기에서 avg만 보고 중요도를 판단하지 않는다.

cpu_ms_inclusive:
  game.update, game.player_update, game.combat, game.interaction
  ai.enemy_update, ai.npc_update, ai.animal_update
  navigation.pathfind, navigation.connectivity, world.map_generation, world.populate
  scene.update, scene.gather, scene.sort, scene.collect_destroyed, scene.render
  render.frame_submit, render.terrain, render.water, render.shadows, render.world
  render.effects, render.postprocess, render.ui, render.queue_flush, render.swap_wait
  render.dynamic_buffer_upload, render.batch_submit
  ui.hud_build, render.minimap, text.submit, text.glyph_rasterize_upload
  cache.hunting_map_build, cache.lake_mesh_build, render.static_mesh_upload
  render.initialize, render.shader_compile, text.atlas_initialize
  asset.material_prepare, asset.character_atlas_prepare, asset.model_atlas_prepare
  asset.disk_load, asset.disk_save, asset.texture_upload
  input.key_down, lifecycle.shutdown

모든 CPU/GPU 구간은 자식 비용을 포함한다.
예: scene.render + render.world + render.queue_flush를 합치면 중복 계산이다.
CPU 제출 시간은 GPU 실행 시간과 다르며 swap 대기도 렌더 계산 시간과 분리해 본다.

gpu_ms_delayed_inclusive:
  지원할 때 render.frame 및 terrain/shadows/world/effects/postprocess/ui의 GPU timestamp 시간.
  결과 준비 여부를 확인한 뒤 읽고 glFinish나 결과 대기를 하지 않는다.
  GPU 구간에는 해당 구간 안의 GPU idle/CPU 제출 지연이 영향을 줄 수 있다.
  결과는 완료된 시점의 집계 창에 포함되므로 CPU 창과 정확히 같은 프레임 집합은 아니다.
  gpu.last_result_age_frames로 결과 지연을 확인한다.
  96개 query 쌍이 모두 대기 중이면 샘플을 생략하고 gpu.query_samples_dropped를 증가시킨다.
  종료 때도 미완료 결과를 기다리지 않으므로 마지막 일부 GPU 샘플은 없을 수 있다.
  gpu_supported=false 또는 samples 없음은 0ms가 아니라 측정 불가/미수집이다.

counters_window:
  render.<pass>.draw_calls / source_primitives: 패스별 비용 분포
  render.draw_calls, render.submitted_indices: 전체 제출 수, 인덱스 수
    (fullscreen 즉시 모드에는 인덱스가 없어 submitted_indices에 포함되지 않음)
  batch.merged_primitives / state_runs / split_texture / split_topology
  batch.flushes / flush_capacity / texture_bind_calls / program_barriers / blend_barriers
    (batch.*는 큐 경로만 센다. 리소스 업로드/직접 후처리 상태 변경의 총계가 아니다)
  upload.dynamic_buffer_bytes / static_buffer_bytes / texture_bytes
  text.glyph_cache_hits / glyph_cache_misses / glyph_evictions / rasterize_failures
  cache.hunting_map_rebuilds / lake_mesh_rebuilds
  scene.actor_updates / actor_draws / hidden_or_culled
    (actor_draws는 Actor::Draw 진입 횟수이며 내용이 없는 그룹 노드도 포함할 수 있음)
  collision.walkable_queries / tutorial_queries
  navigation.segment_queries, game.update_calls
  asset.disk_cache_hits / disk_cache_misses / procedural_generations
  asset.disk_read_bytes / disk_write_bytes / disk_write_failures
  render.shader_compile_failures

gauges_last:
  최신 관측값. 창 전체 합계가 아니다.
  world.map_seed, world.water_indices, scene.actor_count, game.loot_count, game.paused
  render.last_draw_calls, render.last_source_primitives, render.postprocess_enabled
  loop.update_dt_ms, loop.requested_timer_ms
  text.atlas_bytes, text.glyph_resident, cache.hunting_water_bytes, batch.retained_cpu_bytes
  logging.last_write_cpu_ms, logging.file_available
  메모리 gauge는 명명된 리소스만 나타내며 프로세스 전체 RAM/VRAM 사용량이 아니다.

5. AI에게 분석을 요청할 때

current.jsonl과 필요하면 previous.jsonl을 함께 제공한다.
예시 요청:
  "runtime 창에서 프레임당 CPU 비용이 큰 구간을 찾고, inclusive 중복을 제외해 분석해줘.
   draw_calls_per_frame과 패스별 호출 수, batch 분리 이유, 업로드 바이트를 비교해줘.
   game.paused=0 구간에서만 전투 성능을 비교하고 startup/shutdown은 따로 정리해줘.
   GPU 미지원과 누락 샘플을 0ms로 취급하지 말아줘."

6. 이후 기능을 추가할 때

CPU:
  Profiler::Scope scope("inventory.update");
  Profiler::Count("inventory.items_processed", itemCount);
  Profiler::Gauge("inventory.item_count", itemCount);
  새 키와 단위/의미를 이 문서에 추가한다.

GPU:
  먼저 기존 큐를 Flush한다.
  Profiler::GpuScope scope("render.new_pass");
  해당 패스의 실제 제출 뒤에도 Flush한 후 scope를 끝낸다.
  dynamic 문자열/Actor ID를 scope 키로 전달하지 않는다.

프레임 내 매 버텍스에 타이머나 printf를 넣지 않는다.
로그는 집계 후 1초 단위 출력한다. 계측 오버헤드는 --no-profile로 비교할 수 있다.
각 CPU/counter/gauge 키 집합은 128개로 제한한다.

이 계측은 현재 주요 게임/렌더 경로를 감싸는 확장 가능한 계측 기반이다.
모든 함수, OS/드라이버 내부, GPU 하드웨어 카운터, 전체 RAM/VRAM을 자동 분석하는
샘플링 프로파일러는 아니다. 새 시스템은 scope를 추가하고 미계측 병목은 외부 도구로 확인한다.

7. 사용자 빌드/실행 시 검증

- Release와 Debug를 구분하고 같은 해상도/맵 시드/카메라에서 비교한다.
- 첫 레벨 미니맵 바탕의 셀당 1440회 호출이 사라지는지 확인한다.
- 가림/투명도, 그림자, 물결, 불꽃, 후처리, 한글 대화/숫자 HUD를 확인한다.
- N 재생성 때 지도와 물 모양이 바뀌고 cache.hunting_map_rebuilds가 증가하는지 확인한다.
- 맵이 그대로일 때 static_buffer_bytes가 지속 증가하지 않는지 확인한다.
- HP/XP가 바뀌어도 익숙한 숫자/글자는 glyph_cache_hits로 재사용되는지 확인한다.
- --tutorial에서 이동/대화/선택과 R 재시작, 창 크기 변경을 확인한다.
- 정상 종료/재시작 시 GPU 리소스 수명 문제가 없는지 확인한다.
- GPU 지원/미지원 모두 CPU 로그가 나오고 파일 JSONL이 파싱되는지 확인한다.
- fps가 제한되어 있어도 CPU 제출 시간과 draw call이 줄었는지 별도로 비교한다.

최적화 후 실제 FPS, draw call 수, 그래픽 동일성은 빌드/실행 전에는 확정할 수 없다.
